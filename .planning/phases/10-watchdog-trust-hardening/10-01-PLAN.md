<task type="auto">
  <name>Task 2: Manifest floor, revocation list and revoked check in verify_pending</name>
  <files>crates/rmm-watchdog/src/apply.rs, crates/rmm-watchdog/tests/apply.rs, crates/rmm-watchdog/tests/fixtures/, xtask/src/action_fixtures.rs</files>
  <action>
In verify_pending follow the check order from the context decisions. After apply_manifest succeeds read the manifest seq from the store: below state.manifest_seq_floor => StaleManifest; above => raise the floor and save the state immediately. Read revocations.env: apply it to the same TrustStore with apply_revocations (fresh MemorySeqStore; the floor is enforced here from state.revocations_seq_floor) at the current time; any failure, absence or expiry => BadRevocations; a higher seq raises and saves its floor. After verify_release: reject Revoked when store.is_artifact_revoked(envelope content id) or is_artifact_revoked(this platform's artifact sha256). Keep every existing check and reason unchanged. Extend xtask action-fixtures (same deterministic, checked-in policy) with: manifest-old.env (lower seq, includes a release cert that the newer manifest revokes), a release signed by that revoked key, revocations.env (empty list), revocations-artifact.env (lists the 0.1.1 artifact hash), revocations-envelope.env (lists the 0.1.1 release envelope content id), revocations-old.env (lower seq), revocations-expired.env. Tests: every new reason; a stale manifest is rejected even with an otherwise valid release; floors rise and survive reload; an equal manifest seq is accepted; all pre-existing tests still pass with revocations.env added to their staged directories.
