Required interfaces/content structure:
- rmm-sign keygen-root --out <file.age> : generates an Ed25519 seed (OsRng), age-encrypts it with a passphrase (RMM_SIGN_PASSPHRASE or prompt twice), prints public key hex and key_id hex; refuses to overwrite
- rmm-sign pubkey --backend file:<path>|card[:<ident>] : prints public key hex and key_id hex
- rmm-sign sign --type manifest|revocations|techlist|command --in <draft.json> [--prev <old.env>] --backend <..> [--add-to <partial.env>] --out <file.env> [--yes] : parses the JSON draft into the typed document, runs its validate(), shows a unified diff of pretty JSON vs --prev (or the full document), requires typing 'yes' unless --yes, signs, appends the signature to --add-to when given (multi-sig), writes the canonical envelope
- rmm-sign verify --roots <hex,...> --root-threshold N [--manifest <m.env>] <file.env> [--now <unix>] : verifies with rmm_trust::TrustStore and prints signer key ids and the decoded document
- rmm-sign inspect <file.env> : prints envelope metadata and the decoded payload as pretty JSON
- card backend: open via card-backend-pcsc, select by ident when given (else exactly one card must be present), require the signing key algorithm to be Ed25519, verify the user PIN for signing (RMM_CARD_PIN or prompt), print 'Touch your security key to sign...' before PSO:COMPUTE DIGITAL SIGNATURE over the 39-byte message, check the returned key_id matches --expect-key-id when provided
Edge/error cases:
- Wrong passphrase -> clear error, exit 2, no partial output file
- No card present / more than one card without --card ident -> clear error listing idents
- Card signing key is not Ed25519 -> refuse with the found algorithm
- Draft JSON with unknown field -> parse error naming the field (deny_unknown_fields)
- --add-to envelope with a different payload than the draft -> refuse
- --out file exists -> refuse unless --force
