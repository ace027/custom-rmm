<task type="auto">
  <name>Task 2: End-to-end actions</name>
  <files>scripts/e2e-actions.sh</files>
  <action>
scripts/e2e-actions.sh following the conventions of scripts/e2e-telemetry.sh (fake DMI machine, debug agent as root via unshare, built with RMM_ROOT_PUBKEYS from deploy/.env, RMM_AGENT_TEST_PLATFORM=1): enroll and run the agent; create files in the agent's test spool root; then print PASS per check: (1) POST the spooler action -> within 120 s action_run status succeeded, stages precheck/snapshot/steps/verify all ok in order with timestamps, the stored result_envelope verifies (checked by the presence of an audit row action.result for this cmd_id, written only after server-side verification) and the spool files are in the agent's quarantine dir; (2) restart the agent with RMM_AGENT_FAKE_FAIL_START=Spooler, run the action -> status rolled_back, verify stage failed, rollback ok, spool files restored; (3) sign and upload revocations listing the spooler definition's content id with rmm-sign, run the action -> status rejected with reason revoked and no new quarantine dir; (4) issue an action to an agent of another client with a client-scoped token is out of reach (only admin tokens exist), so instead assert that a result published on the agent's result subject by nats-box with a forged signature leaves action_run unchanged. In an EXIT trap the script signs and uploads a fresh empty revocations document with a higher seq, so a rerun against the same dev database is not left with the spooler definition revoked. Add the script to test-linux after e2e-offline.sh in ci.yml and to ci-local.sh.
