Required interfaces/content structure:

- rmm_db::actions::{put_definition, definition_by_content_id, insert_action_run, finish_action_run(tx, cmd_id, status, reason, stages, result_envelope, finished_at) -> bool /* false if already finished */, action_run(tx, cmd_id)}
- PUT /api/v1/catalog, POST /api/v1/agents/{agent_id}/actions -> 202 {cmd_id}, GET /api/v1/action-runs/{cmd_id} -> {status, reason, stages, created_at, finished_at}; 404 for unknown/other-client ids, 409 when the agent is not active, 422 for invalid params or unknown definition
- rmm_server::results::run(): RESULT stream (subjects result.>, max_age 14 d), durable consumer 'results'; per message: parse result.<client>.<agent>, look up the agent (active or revoked allowed: a revoked agent's last results still count) and its credential_pubkey, verify the envelope type rmm.result/1 and signature, require result.agent_id == subject agent and a matching action_run for that agent, finish_action_run, audit; invalid -> term and count
- natsjwt: add $JS.API.CONSUMER.INFO.CMD.agent_<a> to the agent pub allow list
- Consumer management: ensure_agent_consumer(js, agent_id) creates or updates durable pull consumer agent_<agent_id> on stream CMD with filter agent.<agent_id>.cmd, ack explicit, max_deliver 5; called at enrollment and before every issue
Edge/error cases:
- Definition upload with a non-catalog signature or a revoked content id -> 422, nothing stored
- Issue for an agent of another client scope or unknown agent -> 404
- Result signed by a different agent's key -> termed, action_run unchanged
- Duplicate result for a finished run -> acked, no second update
- Command key file missing -> issue endpoint returns 503 and logs once
