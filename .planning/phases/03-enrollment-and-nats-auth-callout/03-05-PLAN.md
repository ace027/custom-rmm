Required interfaces/content structure:
- rmm_server::natsjwt::{encode_jwt(claims: &serde_json::Value, issuer: &nkeys::KeyPair) -> String /* header {typ:JWT, alg:ed25519-nkey}, base64url without padding, claims get iat, iss and jti (base32 of SHA-256 of the unsigned claims) */, decode_authorization_request(jwt: &str) -> Result<AuthRequest> /* AuthRequest { user_nkey, server_id, client_info { host, nonce, .. }, connect_opts { nkey, sig, name, .. } } */, user_claims(user_nkey, agent: &AgentAuthRow, now) -> Value, authorization_response(user_nkey, server_id, user_jwt: Option<String>, error: Option<String>) -> Value}
- authd: subscribes to $SYS.REQ.USER.AUTH as NATS user authd; per request: decode, verify connect_opts.sig (base64url Ed25519 over client_info.nonce) with the key decoded from connect_opts.nkey, look up agent_by_pubkey in a Scope::Service("authd") transaction with a 2 s statement_timeout, require agent status active and client status active, issue the user JWT, touch last_seen, write an audit row (actor authd, action nats.auth.allow or nats.auth.deny), reply with the authorization response signed by RMM_AUTHD_ISSUER_SEED; any error -> deny response with a generic message
- authd also subscribes to rmm.internal.agent.revoked and, with SYS credentials (RMM_NATS_SYS_USER / RMM_NATS_SYS_PASSWORD), requests $SYS.REQ.SERVER.PING.CONNZ with {"user": <nkey>} and sends $SYS.REQ.SERVER.<server_id>.KICK {"cid": n} for each match
- rmm-server gen-nkey --type account|user prints `seed=<S...>` and `public=<A...|U...>` lines (used by dev-up.sh)
- nats.conf: accounts RMM (jetstream enabled, static users api, ingest, authd) and SYS (user sys); authorization { auth_callout { issuer: $RMM_AUTHD_ISSUER_PUBKEY, auth_users: [api, ingest, authd, sys], account: RMM } }
- scripts/nkey-seed.py <raw-seed-file>: prints the NATS user seed string (base32 of prefix bytes 0x90 0xA0 | raw seed | CRC16-XMODEM little-endian, no padding) so the e2e test can impersonate the agent with nats-box
Edge/error cases:
- Agent key connecting over plain TCP 4222 -> denied by connection type
- Agent key publishing to another agent's telemetry subject -> permissions violation
- Revoked agent reconnecting -> denied; a connected agent is kicked within 5 s of revocation
- Agent of client A subscribing to shell.<agent of client B>.*.in -> permissions violation
- Database down -> authd denies and stays running; its /healthz reports 503 while NATS or the last DB check is failing
