Required interfaces/content structure:
- POST /api/v1/enrollment-tokens (RMM.Admin) body {client_id, site_id, expires_in_hours (1..720), max_uses (1..1000), allow_reattach} -> 201 {token, token_id, expires_at} (token shown once)
- POST /v1/enroll (no auth; body EnrollRequest JSON, max 16 KiB) -> 201 EnrollResponse | 400 invalid | 401 bad token or proof | 409 pubkey already enrolled | 429 (rate limit is nginx's; API returns 429 only from its own per-IP limiter of 10/min)
- POST /api/v1/agents/{agent_id}/revoke (RMM.Admin) -> 204; publishes rmm.internal.agent.revoked {agent_id, nkey} on NATS
- PUT /api/v1/trust/{kind} (RMM.Admin, body application/octet-stream envelope) -> 204 after verifying with rmm_trust::TrustStore built from RMM_ROOT_PUBKEYS (comma-separated hex) and RMM_ROOT_THRESHOLD plus the stored artifacts; 422 with the TrustError otherwise
- rmm_api::auth::{Claims { sub, oid, name, roles }, Authenticator (Entra JWKS cache + optional dev key), require_role(role) extractor}; rmm_api::enroll::decide(matches: &[DeviceMatch], token: &TokenRow, fp_strength, now) -> AttachDecision { New, Reattach { device_id, old_agent_id }, PendingReview { possible_clone_of }, NewFlagged } (pure)
- rmm_api::router(state: AppState) -> Router; AppState { pool, authenticator, nats: Option<async_nats::Client>, roots, nats_public_url }
- rmm-server dev-token --role RMM.Admin --sub dev-admin [--ttl 3600] prints an RS256 JWT signed with RMM_AUTH_DEV_KEY_FILE (PEM), issuer rmm-dev, audience RMM_ENTRA_AUDIENCE
Edge/error cases:
- Stolen token used after max_uses -> 401 and audit row
- Expired token -> 401
- Valid token but proof signed by a different key -> 401 without consuming the token
- ts 301 s old -> 400
- Same agent_pubkey enrolling twice -> 409
- Strong fingerprint match in another client -> NewFlagged (never reattached)
- Weak fingerprint -> New even if a device matches
- JWT with wrong audience, expired, unknown kid after refetch, alg none or HS256 -> 401
- Dev token when RMM_AUTH_ALLOW_DEV is unset -> 401

Implement the routes per the interfaces with utoipa annotations. Token generation: 20 random bytes from OsRng, base32 (data-encoding BASE32_NOPAD) -> 32 chars, prefix rmmenr_. Enroll flow: size limit, parse, ts window, verify proof (ed25519-dalek verify_strict over signing_bytes), compute fingerprint with rmm_proto::enroll::fingerprint, open Scope::Service("enroll") transaction, consume token (401 if None), find devices by fingerprint, decide(), insert/reattach device and agent (nkey = nkeys public user key encoding of agent_pubkey), audit, commit, return EnrollResponse with latest trust artifacts and RMM_NATS_PUBLIC_URL. Revocation sets status revoked in a Scope::Service transaction, audits, publishes the NATS message when a client is configured (log a warning otherwise). Trust upload builds a TrustStore from configured roots, replays stored artifacts in seq order, applies the new one, then stores it. tests/enroll.rs uses #[sqlx::test(migrations = "../rmm-db/migrations")] with the router and tower::ServiceExt::oneshot: happy path, every enrollment edge case in the plan, reattach after 24 h, pending_review when the old agent was seen recently, cross-client NewFlagged, revocation status change, trust upload accepted for a valid manifest built with rmm-trust sign fixtures (dev-dependency rmm-trust features sign) and rejected for a tampered one.
