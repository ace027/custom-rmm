<task type="auto">
  <name>Task 2: Session pump with backpressure, liveness and max_duration</name>
  <files>crates/rmm-agent-core/src/shell.rs, crates/rmm-agent-core/Cargo.toml, crates/rmm-agent-core/tests/shell_session.rs</files>
  <action>
Implement ShellManager in shell.rs. Per session: spawn the PTY via rmm_platform::pty::spawn_shell (or a factory injected for tests that returns FakePty); a blocking reader thread reads into a buffer of at most max_chunk and sends chunks over a bounded channel of capacity 1; the async pump coalesces up to max_chunk bytes or chunk_interval, assigns seq, and publishes ShellOut::Data only while unacked bytes + chunk <= max_in_flight, otherwise it waits for ShellCtl::Ack/Window before taking more from the reader (so the reader blocks and ConPTY blocks the child). ShellIn::Data writes to the PTY, Resize resizes. Ping resets the liveness deadline; no Ping for liveness => Closed{reason:'liveness'}; max_duration elapsed => Closed{reason:'max_duration'}; Close => Closed{reason:'closed_by_relay'}; child exit => Exit{code}. Teardown kills the child, drops subscriptions, and updates the indicator (connected with tech while any session is open, idle otherwise). on_techlist closes sessions whose tech or credential is no longer listed with Closed{reason:'tech_removed'}. At most 2 concurrent sessions. Tests with the in-memory ShellLink and FakePty: 1 GiB of output with a relay that acks slowly never exceeds max_in_flight unacked bytes, and the process peak RSS growth (VmHWM from /proc/self/status, Linux only) stays under 50 MB; liveness timeout fires with a 1 s test liveness; max_duration fires with a 2 s grant; input reaches the PTY; tech removal closes the session; a third concurrent session is rejected; the indicator receives connected then idle.
