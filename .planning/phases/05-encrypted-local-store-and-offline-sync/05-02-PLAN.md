Required interfaces/content structure:
- Migration 0004: ts_private.ingested_msg(msg_id uuid primary key, received_at timestamptz not null default now()); index on received_at; GRANT SELECT, INSERT, DELETE to rmm_ingest; nothing to rmm_api
- rmm_db::telemetry::{claim_msg_ids(tx, ids: &[Uuid]) -> Result<HashSet<Uuid> /* ids newly claimed */> using INSERT ... ON CONFLICT DO NOTHING RETURNING, prune_ingested(tx, older_than: DateTime<Utc>) -> Result<u64>}
- Ingest: per batch, claim msg_ids for inv and metric items in the same transaction as the writes; items whose id was already claimed are acked without writing (counted as duplicates); a prune of rows older than 7 days runs at most once per hour
- Agent: Publisher::enqueue(kind, msg) writes to the outbox (spawn_blocking) and wakes the drain task; drain task publishes outbox_peek rows with Nats-Msg-Id, deletes each on ack, backs off 1 s..30 s on failure, and drains immediately on reconnect
Edge/error cases:
- Ack lost after the server stored the message -> the re-publish is deduped by ingested_msg
- Agent restarted while offline -> queued rows survive and drain after the next connect
- Outbox full while offline -> oldest metrics dropped and counted; inventory kept
- Ingest crash after writing but before acking -> redelivery is deduped
