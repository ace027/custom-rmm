update.rs: given a verified release (from the refresh callback) skip it when its version is not newer than current_version (Downgrade/UpToDate), when the watchdog state.json (read-only) lists its hash in bad_hashes (KnownBad), or when pending/READY already exists; otherwise download GET {api_base}/v1/artifacts/{hex} with the existing reqwest client and the agent's extra CA (size cap = artifact.size, abort above it), hash while writing pending/<name>.part, compare size and SHA-256 (mismatch => delete and Failed('hash_mismatch')), then write release.env and manifest.env, rename the artifact, and write READY last. health.rs: write health.json after each successful heartbeat publish (hook into telemetry.rs where the heartbeat is published). Wire the refresh callback and RMM_WATCHDOG_ROOT (default: parent of the state dir on unix, %ProgramData%\RMM on Windows) in main.rs; when no watchdog root exists, log once and skip updates. Tests with a local axum or hyper test server are not available in agent-core deps, so use a tiny std TcpListener HTTP responder in the test: newer release stages pending with READY last; tampered bytes are rejected and leave no READY; older version skipped; known-bad skipped.
